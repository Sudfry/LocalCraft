# LocalCraft 架构说明（C 实现）

> 纯 C11 + Win32 + Winsock，无第三方库依赖，单文件 exe。

---

## 1. 一句话架构

**所有功能都是「规则 → 计划 → 预览 → 执行 → 日志 → 可回退」这条流水线上的插件。**

```
   用户规则
      │
      ▼
 ┌──────────┐   rename.c / organize.c /（未来）convert.c / dedup.c
 │ 规则模块  │   只负责"算出应该怎么动"，绝不碰文件
 └────┬─────┘
      │ Action（src → dst）
      ▼
 ┌──────────┐   planner.c
 │ 计划构建  │   冲突分析 · 策略决策 · 拆解为原子步骤
 └────┬─────┘
      │ Plan
      ▼
 ┌──────────┐   api.c → webui
 │ 预览对照  │   旧状态 → 新状态 · 冲突标色 · 人工勾选
 └────┬─────┘
      │ 用户确认
      ▼
 ┌──────────┐        ┌───────────┐
 │  执行器   │───────▶│  回退日志  │  JSONL · 每步 FlushFileBuffers
 │executor.c│        │journal.c  │
 └────┬─────┘        └─────┬─────┘
      │                    │
      ▼                    ▼
 ┌────────────────────────────────┐
 │ rollback.c：读日志 → 逆序取反   │
 └────────────────────────────────┘
```

**关键设计：模块之间只通过 Plan / Action 通信，谁都不直接动文件。**
于是"可回退"是白得的 —— 不用给每个功能单独写撤销逻辑。

## 2. 内存模型：Arena

程序内部不流行 `free()`。每份 `Plan` 配一个 `Arena`：

```c
Arena *a = arena_new();
Plan  *p = rename_build_plan(a, root, &rule, policy, NULL);
...
arena_free(a);          /* 一次性全部回收 */
```

* 块式 bump 分配，块大小 64 KB 起，`arena_alloc` 永不单独 free；
* 一个 Plan 里上千个 Action / Step / 字符串，回收只走一条路径；
* **只有明确知道自己 malloc 的东西才 free**。

> 踩过的坑：早期版本在 rollback 里手滑对 arena 指针调了 `free()`，
> 直接触发 `STATUS_HEAP_CORRUPTION`。现在的约定是：
> **`Action` / `Plan` 里的所有字符串都来自 arena，绝不能 free。**

## 3. 编码与路径

* 程序内部**一律宽字符**（UTF-16）—— Windows 原生 API 就是 `W` 版本，中文路径不会乱码。
* 只在**进程边界**（JSON / HTTP）转换成 UTF-8。
* 所有对 `CreateFileW` / `MoveFileExW` / `DeleteFileW` 的调用都先经过
  `lc_long_path()`，必要时自动加 `\\?\` 前缀，绕过 260 字符限制。
* `lc_sanitize_component()` 处理非法字符、结尾的点和空格、`CON`/`NUL`/`COM1` 这类保留名。
* **大小写语义分两种**：
  * `lc_same_path()` —— 大小写不敏感，用于判断"是不是同一个文件"（身份）；
  * `lc_same_path_exact()` —— 大小写敏感，用于判断"是否真的需要改名"。
  * 混用会导致 `MyFile.txt → myfile.txt` 这种仅大小写重命名被当成空操作跳过。

## 4. 冲突分析（planner.c）

顺序很重要：

| 步骤 | 做什么 | 为什么这个顺序 |
|------|--------|---------------|
| 1 | 静态校验 | 源缺失 / 非法名 / 目录移入自身 / 目标是已存在目录 |
| 2 | **链式移动检测** | 必须早于策略处理：否则 `a→b`、`b→c` 会被 RENAME 策略悄悄改成 `a→"b (1)"`，表面无冲突，实际与用户意图不符 |
| 3 | 目标已存在 → 按策略处理 | ask / skip / overwrite / rename |
| 4 | 批次内重复目标 | 两个操作算出同一个 dst → 全部标红，逼用户改规则 |
| 5 | 拆解为原子步骤 | 建目录 + （可选）回收站 + 移动 |

### 冲突级别

| 级别 | 含义 | 效果 |
|------|------|------|
| `ok` | 正常 | 可执行 |
| `info` | 提示（自动改名、无需操作） | 可执行 |
| `warn` | 警告（覆盖、长路径、体积不符） | 可执行，但界面标黄 |
| `error` | 冲突（源缺失、重复目标、非法名…） | **阻止执行** |

## 5. 执行器与日志（executor.c / journal.c）

* 执行前**每一步重新校验**（源还在吗？目标还没被别人占吧？）——
  从"预览"到"点执行"之间磁盘状态会变。
* 目标已存在时**绝不覆盖**（除非计划里显式带了回收站步骤）。宁可失败，也不丢用户文件。
* 每个动作执行完立即 `journal_step(...)`，内部 `WriteFile` + `FlushFileBuffers`。
* **跳过的步骤不写日志** —— 日志里只放"真正发生过的事"，否则重做会多做一次。
* 单步失败不影响后续动作（可配 `stop_on_error`），失败本身也记进日志。

## 6. 回退（rollback.c）

逆操作对照：

```
MOVE(src → dst)  ⟹  MOVE(dst → src)
COPY(src → dst)  ⟹  MOVE(dst → 回收站)
MKDIR(dst)       ⟹  RMDIR(dst)        （lenient：非空则自动跳过）
RMDIR(dst)       ⟹  MKDIR(dst)
CREATE(dst)      ⟹  MOVE(dst → 回收站)
```

### `lenient` 步骤

回退计划是在**执行之前**算出来的，那时目录里往往还有文件。
所以 RMDIR 步骤标了 `lenient`：真正回退时如果目录仍非空，就记作"跳过"而不是"失败"，
并且**绝不递归删除**。

### 逆序 + 集合法校验

倒序遍历成功步骤，同时维护两个集合：

* `freed` —— 已经让出来的位置（前面的逆操作腾空的）；
* `occupied` —— 已经占用的位置。

逆操作的目标位置若被别人占用且不在 `freed` 里 → 跳过并提示，不动任何文件。

### 回退也可回退

回退写的是 `rollback-<新id>_undo_<原id>.jsonl`，文件名里带着原计划 id，
界面据此判断"这条记录已经被回退过"。因为回退本身也是日志，
**再回退它一次就是「重做」**。

## 7. HTTP 服务与 API（http.c / api.c）

```
GET  /                     → 内嵌的 index.html（要令牌）
GET  /static/<file>        → 内嵌的 CSS/JS（不要令牌，不含用户数据）
GET  /api/ping             → 存活探测（要令牌）
POST /api/call             → {"method":"...","params":{...}}（要令牌）
```

* 线程模型：一个 accept 线程，每个连接一个线程。
* `SO_EXCLUSIVEADDRUSE` + 只 `bind` 到 `inet_addr("127.0.0.1")`。
* 每次启动 `CryptGenRandom` 生成 32 字符令牌，`/` 与所有 API 校验。
* 检查 `Origin` 头，拒绝其它网页的跨站调用。
* **全局锁只用于保护会话表与任务表**，绝不跨文件对话框持有 ——
  否则打开"选择文件夹"对话框时，界面轮询 `job.status` 会一起卡死。

### 会话与任务

* `PlanSession` —— 当前预览的计划 + 重建所需的规则（换策略时要重算），1 小时过期。
* `Job` —— 后台执行线程，界面每 200 ms 轮询 `job.status` 拿进度。
* 看门狗：界面窗口关掉后（心跳停止 10 分钟）自动退出；**有任务在跑时绝不退出**。

## 8. 界面层

* 资源**内嵌**进 exe（`tools/embed.c` 在构建期把 `webui/` 转成 C 字节数组），
  所以发布只有一个文件。开发时如果 exe 同级有 `webui/` 目录，则优先读磁盘，改完刷新即可。
* 窗口用 `msedge.exe --app=<url>` 打开：**无地址栏、无标签页、无工具栏**，
  独立 `--user-data-dir`，不干扰用户自己的浏览器配置。
* 降级链：Edge 应用模式 → Chrome 应用模式 → 系统默认浏览器 → 打印地址。
* 子系统是 `WINDOWS`（双击不闪黑框）；需要控制台时用 `AttachConsole(ATTACH_PARENT_PROCESS)`
  挂到父进程控制台上，`--headless` 与 `--version` 都能正常输出。

## 9. 已知约束与踩过的坑

* **MinGW 没有 `regex.h`**，所以正则引擎是自己写的（`regex.c`）。
* **MinGW 的宽字符 printf 里 `%s` 按窄字符串处理**，给 `wchar_t*` 必须用 `%ls`。
  这个坑很隐蔽：`L"%.*s"` 会把 `L".txt"` 输出成 `.`（读到一个字节就遇到 NUL）。
* **JSON 拼接必须自己管逗号**。`put_key_*` 系列不自动加前导逗号，
  漏一个就整个响应解析失败 —— 这类错误只有集成测试才抓得到。
* 外部转换引擎（Pandoc / LibreOffice / FFmpeg / LibRaw）**尚未接入**，
  界面与 API 会如实报告"未接入"，不会假装可用。
